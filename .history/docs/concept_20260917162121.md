# Build `dityalearnrobot.com`

Create a minimal personal learning wiki and engineering log website called **Ditya Learns Robotics**.

## Core idea

This is NOT a portfolio website and NOT a social media website.

It is a simple public wiki / engineering notebook where I document:

* what I am learning
* what I am building
* what I experiment with
* what I discover
* selected research notes

The website should feel like **personal technical documentation**, similar to a clean developer documentation website.

The philosophy is:

> **Learn. Build. Document.**

The website should be extremely simple, calm, readable, and content-first.

---

# 1. Design direction

## Visual style

Use a **white-first interface**.

Requirements:

* white background
* black / near-black text
* subtle gray borders
* muted gray secondary text
* one subtle muted teal accent
* no gradients
* no glassmorphism
* no excessive shadows
* no colorful cards
* no 3D graphics
* no robot illustrations
* no animated backgrounds
* no excessive animations
* no huge hero section

The website should feel closer to:

* technical documentation
* engineering notebook
* developer wiki
* research notes

rather than:

* startup landing page
* personal branding site
* modern SaaS dashboard

Use generous whitespace and strong typography.

# 6. Learning status

Use only four simple statuses:

```text
Not started
Learning
Practicing
Comfortable
```

Do NOT use percentage progress bars.

Do NOT create gamification.

Do NOT create points, XP, streaks, badges, or achievements.

The purpose is reflection, not productivity gamification.

# 10. GitHub integration

GitHub should be an important part of the website.

The website is the **documentation layer**.

GitHub is the **artifact/source layer**.

Relationship:

```text
Website
    ↓
Explanation
    ↓
Photos
    ↓
Experiments
    ↓
Results
    ↓
GitHub
    ↓
Code / CAD / PCB / Scripts
```

Every project should have a:

```text
View on GitHub →
```

link.

Where practical, show basic repository information such as:

* repository name
* description
* main language
* last updated
* GitHub link

Do not create a complicated GitHub dashboard.

# 13. GitHub workflow

The intended workflow is:

```text
Learn something
      ↓
Write Markdown
      ↓
Add image/video if useful
      ↓
Commit
      ↓
Push to GitHub
      ↓
Automatic deployment
      ↓
Website updated
```

The site should be deployable through Vercel or another static hosting provider.

No database is required.

No authentication is required.

No admin dashboard is required.

---

# 14. Technology

Prefer a static documentation architecture.

Recommended:

* Astro + Starlight OR VitePress
* Markdown / MDX
* GitHub
* Vercel

Choose the simpler option if there is a tradeoff.

Avoid introducing unnecessary dependencies.

# 19. Important philosophy

The website should feel unfinished by design.

New content should be easy to add.

Do not optimize for having a huge amount of content.

The goal is:

> **Consistent documentation over time.**

A short useful note is better than a long polished article.

A failed experiment is worth documenting.

A photo of a prototype is useful.

A graph from an experiment is useful.

A short explanation of something I finally understood is useful.

# 22. Final design principle

When deciding whether to add a feature, ask:

> **Does this help me learn, build, or document?**

If not, don't add it.

The final website should feel like:

**GitHub Docs × personal engineering notebook × simple wiki**

with a very clean white interface.

The website should prioritize **content, evidence, and long-term growth** over visual effects.
